# 示例库协议化重构：从「SQL 示例库」到「查询示例库」

## 核心思路

将 `data_training`（示例库）纳入协议抽象体系，让每个协议声明自己需要什么类型的示例、如何检索。不是加一个字段打补丁，而是让示例库成为协议架构的有机组成部分。

字段命名：`training_type`（值为 `'sql'` / `'rest'`）

---

## 架构变更总览

```
BaseProtocol
  ├── training_type: str = "sql"             # 新增：协议声明自己需要的示例类型
  └── build_prompt_bundle()                   # 已有：各协议用自己的模板包装示例

SqlProtocol.training_type = "sql"             # 默认值
RestProtocol.training_type = "rest"           # 显式声明

filter_training_template()                    # 从 self.protocol.training_type 获取类型
  → get_training_template(training_type=...)  # 透传
    → select_training_by_question(training_type=...)  # SQL/向量检索加过滤
```

---

## 变更详情

### 1. BaseProtocol：增加 `training_type` 属性

**文件：`backend/apps/protocol/base.py`**

```python
class BaseProtocol(ABC):
    ...
    training_type: str = "sql"  # 协议对应的示例库类型
```

**文件：`backend/apps/protocol/rest/protocol.py`**

```python
class RestProtocol(BaseProtocol):
    ...
    training_type = "rest"
```

### 2. 数据模型：增加 `training_type` 列

**文件：`backend/apps/data_training/models/data_training_model.py`**

- `DataTraining` 表增加 `training_type: Optional[str] = Field(max_length=16, default="sql")`
- `DataTrainingInfo` 增加 `training_type: Optional[str] = "sql"`
- `DataTrainingInfoResult` 增加 `training_type: Optional[str] = "sql"`

**新增 Alembic 迁移：`backend/alembic/versions/071_data_training_training_type.py`**

```python
op.add_column('data_training', sa.Column('training_type', sa.String(16), server_default='sql'))
```

旧数据自动保持 `training_type='sql'`，完全兼容。

### 3. 检索层：协议感知过滤

**文件：`backend/apps/data_training/curd/data_training.py`**

- `select_training_by_question()` 增加 `training_type: Optional[str] = None` 参数
  - ILIKE 查询：当 `training_type` 非空时追加 `AND training_type = :training_type`
  - 向量查询：同上
  - 不传时不过滤（向后兼容）
- `get_training_template()` 增加 `training_type: Optional[str] = None` 参数，透传
- `to_xml_string()` 根标签从 `'sql-examples'` 改为 `'examples'`，子元素从 `'sql-example'` 改为 `'example'`

### 4. LLM 流水线：从协议获取示例类型

**文件：`backend/apps/chat/task/llm.py`**

```python
# filter_training_template() 中：
self.chat_question.data_training, example_list = get_training_template(
    _session, self.chat_question.question, calculate_oid, calculate_ds_id,
    training_type=self.protocol.training_type  # 从协议实例获取
)
```

关键融合点——检索逻辑不再硬编码类型，而是从协议实例获取。

### 5. 提示词模板：协议特定表述

**文件：`backend/templates/template.yaml`**

SQL 部分保持不变：
```yaml
generate_data_training_info: |
  以下是你可以参考的SQL示例：
  {data_training}
```

API 部分改为：
```yaml
generate_data_training_info: |
  以下是你可以参考的接口调用示例：
  {data_training}
```

### 6. 前端 UI：类型感知

**文件：`frontend/src/views/system/training/index.vue`**

- 表格新增「类型」列：显示 training_type 标签（SQL 示例 / API 示例）
- 新增/编辑表单增加 `training_type` 下拉选择器
- `description` 字段的 label 和 placeholder 根据 training_type 动态变化：
  - SQL → label="示例 SQL"，placeholder="请输入示例 SQL 语句"
  - REST → label="示例调用"，placeholder="请输入示例接口调用，如 curl 命令、JSON 请求/响应示例"
- 详情抽屉同理

### 7. i18n 国际化

**前端各语言文件**新增：
```json
"training_type": "示例类型",
"type_sql": "SQL 示例",
"type_rest": "API 示例",
"sample_call": "示例调用",
"sample_call_placeholder": "请输入示例接口调用"
```

**后端 `locales/`** 同步新增。

### 8. 导入/导出适配

**文件：`backend/apps/data_training/api/data_training.py`**

- 导出 Excel：增加 `training_type` 列
- 导入模板：增加 `training_type` 列（默认填 `sql`）
