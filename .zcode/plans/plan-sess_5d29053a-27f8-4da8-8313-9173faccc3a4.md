# Conversation Core 回顾审计 + 统一优化方案

## 一、问题本质（这次 embedding 踩坑说明什么）

运行时 `LLMService.__init__() got an unexpected keyword argument 'embedding'` 暴露的不是「漏了一个 kwargs」，而是系统性失误模式：

1. **只改接收端、不看调用图** → TypeError  
2. **把“本文件未引用”当死代码删除** → 可能误杀真实链路（用户纠正是对的态度）  
3. **反矫枉过正**：在未画出端到端效果图前，又把 API 侧 embedding 整条链掐掉，把“历史上已是僵尸的参数”与“召回仍在生效的真路径”混为一谈  

**事实核对（关键）：**

| 层 | 结论 |
|----|------|
| `LLMService.embedding`（含 HEAD） | **早已僵尸**：签名曾接受，**从未** `self.embedding = ...`，`choose_table_schema`/`match_table_schema` **从未转发** |
| 真实表召回 | `match_table_schema` → `protocol.retrieve_schema(embedding default True)` → `get_table_schema` → `settings.TABLE_EMBEDDING_ENABLED` 才 `calc_table_embedding` |
| 真实 DS 召回 | `select_datasource` 仅看 `settings.TABLE_EMBEDDING_ENABLED` + `get_ds_embedding`，与 API flag 无关 |
| 图节点 chart | `nlq.py` **硬编码** `embedding=False` + 已绑定 `plan.resources`（子集重取，不应再排序） |
| 当前脏状态 | `__init__` 已无 `embedding`；API 已不传 → **重启后不再 TypeError**；**主 NLQ 表召回行为与 HEAD 实际效果等价**（仍靠 protocol default + settings） |

因此：**不要复活 `LLMService(embedding=)`**（那是半成品双轨）；要在架构上**正式认定**召回开关归属，并扫清同类半清理。

治理约束不变：禁止补丁式修改；禁止多路实现；禁止兼容层；Core 无业务逻辑；Config 无 execSql；保留 SSE 与 FIT2CLOUD license/logo。

## 二、同类问题全量审计结果

### A. CONFIRMED（必须改）

#### A1. `create_chat` config 免 DS 判断顺序错误（真回归）

`backend/apps/chat/curd/chat.py`：

```python
if not create_chat_obj.datasource and require_datasource:
    raise ...                      # 先 raise
...
if chat_type == "config":
    require_datasource = False     # 太晚
```

- FE `start_chat` 因 API 侧先算 `require_ds = chat_type != "config"` 暂时绕过  
- **任何**直调 `create_chat(..., require_datasource=True)` + `chat_type=config` + 无 DS 仍炸  
- **双真理源**：API 门闸 + curd 覆盖，且次序反了  

**单路径修法**：先解析 `chat_type`，config 强制 `require_datasource=False`，**再**做 DS None 检查。真相源只在 curd。

#### A2. 召回策略所有权未收口（设计债，非当场 TypeError）

当前 chat 层对 embedding 仍有「隐式 default True + chart 显式 False」两套姿势；settings 名 `TABLE_EMBEDDING_ENABLED` 同时管 **表**与 **DS**。未形成「一步 match + 一处 settings」文档化契约。见第三节方案 B。

#### A3. 常量/注释半清理（同源症）

| 点 | 问题 |
|----|------|
| `DYNAMIC_DS_TYPES` | `steps/datasource.py` 权威；`curd/chat.py` 仍 inline `(1, 3)`；`llm.py` 再 import |
| `llm.py` | `from ... DYNAMIC_SUBSQL_PREFIX` **未使用** |
| `permissions.py` 注释 | 仍写 `Keep in sync with LLMService.dynamic_subsql_prefix`（属性已不存在） |
| `create_chat` assistant 分支 | 仅 `type == 1`，与 `DYNAMIC_DS_TYPES=[1,3]` 不对称（历史债，一并顺） |

### B. NOT regression（明确不回滚）

| 项 | 判定 |
|----|------|
| 去掉 `LLMService`/`API` 的 `embedding` 参数 | **正确方向**（参数本无业务效果）；禁止为消 TypeError 再加兼容层吞 kwargs |
| `LLMService.create(..., True)` recommend | 一直是 **`no_reasoning`**，不是 embedding |
| `finish_step` / `return_img` / `in_chat` / `stream` | 仍经 graph state + `resolve_sink`，未静默丢掉 |
| `run_task*` 产品双路径 | 已无；入口 `submit_graph` |
| P1/P2（抽屉标题 + `get_sample_data`） | **已落地**，本方案不重做 |

### C. SUSPECTED（本阶段可选收敛，不扩 scope）

1. Graph 注册依赖 `chat.api` import 副作用 → 更稳是 `main`/bootstrap 显式 `import apps.chat.graphs` + `config_assistant`  
2. protocol 文档仍写 `init_messages`，实现是 `build_context`/`build_prompt_messages`  
3. ConfigAnswer 仍 strip 历史 `**tool-call**` markdown（只读兼容，不双写）——可保留到数据洗清  
4. 外部若当 lib 调 `create(..., embedding=)` 会 TypeError；in-repo 已干净 → **不做 kwargs 吞没兼容层**，changelog 一句即可  

### D. 已完成且应保持的边界（勿再动）

- Config：ChatLog `TOOL_CALL`/`CONFIG_AGENT` 单通道；`choose_tables` `add|remove|set`；无 execSql  
- FE：`stepDisplayName`、`LogToolCall` 唯一 pretty JSON  
- 多图表 Report：**继续 defer**，不进 config

## 三、Embedding / 向量召回：唯一架构结论（选项 B）

### 产品定位

表/DS embedding 召回 = **部署级检索策略**（同 terminology top-k），**不是**用户每条 question 的意图参数，也不是 `RunState` 业务字段，更不是 `LLMService` 构造参数。

### 选项对比（治理对齐）

| 选项 | 内容 | 决定 |
|------|------|------|
| A | 恢复 API + `LLMService.embedding` 并真正 wire | **拒**：复活双轨、兼容层气味、core 邻近堆业务 |
| **B** | **settings 唯一开关**；steps 不传业务级 override；protocol/CRUD 机制参数可保留默认 | **采纳** |
| C | `RunState.embedding` | **拒**：污染最小 RunState；场景态第二路径 |

### 目标拓扑（单路径）

```
settings.TABLE_EMBEDDING_ENABLED  (+ COUNT)
        │
        ├─ steps/datasource.select_datasource  → get_ds_embedding（设置开才跑）
        │
        └─ steps/schema.match_table_schema
                → protocol.retrieve_schema()     # 调用方不传 embedding；默认 True
                    → get_table_schema
                        → if embedding and TABLE_EMBEDDING_ENABLED: calc_table_embedding

chart 再取 schema：
  仅 resource_names / table_list 过滤；不基于 embedding 重排
  → 去掉 graph 上 embedding=False 的「第二姿势」
     （子集列表下 rank 本就是 no-op；靠绑定资源表达意图，不靠 bool）
```

**不进入**：`apps/conversation/*`、`LLMService.__init__`、HTTP query body 的 per-request embedding。

### B 落地改动（完整，非补丁）

1. **API / LLMService（保持现状，补契约注释）**  
   - 不恢复 `embedding=`  
   - `llm.py` / `chat.py` 一处模块注释写明：表/DS 召回仅 `TABLE_EMBEDDING_ENABLED`  

2. **`steps/schema.match_table_schema`（主入口，已正确）**  
   - 继续 **不传** `embedding`  
   - 文档字符串写清依赖 protocol default + settings  

3. **`graphs/nlq.py` chart 节点**  
   - 删除 `embedding=False` 关键字（两处 ~556/565）  
   - 仍只传 `table_list` / `resource_names=plan.resources`  
   - optional 后续：若 `llm_service.chat_question.db_schema` 已够用可免二次 retrieve（本阶段以去 override 为准，不强制合并缓存）

4. **protocol / CRUD**  
   - `retrieve_schema(..., embedding: bool = True)` **可保留为机制参数**（protocol-internal）  
   - 规则：**chat/graphs/steps 层禁止再传 embedding=**（除未来真有「内部 helper 子集重排」并写在 schema step 内）  
   - `get_table_schema` 门闸不变：`embedding and settings.TABLE_EMBEDDING_ENABLED`  

5. **Assistant out-DS**  
   - `get_db_schema` 内 table embedding 调用已注释 → embedding 参数惰性  
   - 本阶段：**不**半开半关；要么另开任务重接 `calc_table_embedding`，要么删死参并在 protocol out-ds 分支统一不装作支持  
   - 推荐本阶段：**文档标明 out-ds 不做表向量召回**；去掉误导性 `embedding=` 透传（`sql/protocol.py` out_ds 分支）若参数无消费  

6. **测试**  
   - `TABLE_EMBEDDING_ENABLED=False` 时 mock：`calc_table_embedding` / `get_ds_embedding` 不被调  
   - `True` + 有表向量时 match 路径会调（可 unit mock）  
   - chart 路径带 `resource_names` 时不依赖 embedding kw  
   - **禁止** 再测 API `embedding=` 参数

## 四、其余统一清理（与 embedding 同治理 sweep）

### C1. `create_chat` 单真相源（P0）

```python
def create_chat(..., require_datasource=True, ...):
    chat_type = (create_chat_obj.chat_type or "chat").strip() or "chat"
    if chat_type not in ("chat", "config"):
        raise ...
    if chat_type == "config":
        require_datasource = False   # 先于 DS 检查

    if not create_chat_obj.datasource and require_datasource:
        raise Exception("Datasource cannot be None")
    ...
```

API 仍可预计算 `require_ds`（冗余但无害）；**行为以 curd 为准**。补测试：`create_chat(chat_type=config, ds=None, require_datasource=True)` 成功。

### C2. `DYNAMIC_DS_TYPES` 单导出（P1）

- 唯一定义：`apps/chat/steps/datasource.py::DYNAMIC_DS_TYPES`  
- `curd/chat.py`：import 该常量，删 inline `(1, 3)`  
- 注意 **circular import**：若 curd ← steps 成环，则抽 `apps/chat/constants.py`（或 `apps/chat/ds_types.py`）只含常量，steps/curd/llm/graphs 共引——**一住一处，无第三份**  
- `create_chat` assistant 分支 `type == 1` → `type in DYNAMIC_DS_TYPES`（与 select 一致）  
- 去掉 `_DYNAMIC_DS_TYPES` 别名若无意义  

### C3. 死 import / stale 注释（P1）

- 删 `llm.py` 未用 `DYNAMIC_SUBSQL_PREFIX` import  
- `permissions.py` 注释改为指向本模块常量  
- protocol docstring `init_messages` → 现行 API 名（捎带）  

### C4. Graph 注册（P2，可选同 PR）

- `main.py` 或 chat 包 `__init__` **显式**注册 graphs / config_assistant，避免仅靠 router import  
- 不引入第二 registry  

### C5. 明确不做

| 项 | 原因 |
|----|------|
| `LLMService(..., embedding=)` 恢复或 `**kwargs` 吞没 | 兼容层 / 假合同 |
| RunState / conversation core 塞 embedding | core 无业务 |
| 拆 `DS_EMBEDDING_ENABLED` 新配置 | 可后续产品化；本阶段不扩 settings 面 |
| config 挂 chart / multi-report | 产品边界已钉死 |
| 大改 assistant out-ds 表向量 | 另任务；本阶段只消误导透传 |

## 六、验收标准

**行为**

- 对话不再因 embedding kwargs 崩溃（已满足，保持）  
- `TABLE_EMBEDDING_ENABLED=True` 时：多 DS 可选 embedding 排序；表 match 仍可走 `calc_table_embedding`  
- `False` 时：上述路径均不调用 embedding 计算  
- chart 生成不依赖第二套 embedding 开关姿势  
- `create_chat(chat_type=config, datasource=None)` 在 default `require_datasource=True` 下成功  

**结构**

- 全仓 **一份** `DYNAMIC_DS_TYPES`  
- **零** `LLMService.embedding` / API embedding 参数（无兼容吞没）  
- Core / config 边界无回潮  
- 无第二 pretty JSON / 无 tool_trace 写路径  

**过程教训（写入本方案而非 AGENTS 空话）**

删除参数前必须：调用图 → 是否 `self.x` → 下游是否读 → settings/protocol 是否已是真相源；**僵尸参数删除可以，但必须整链一致且用文档钉死新真相源，而不是静默掐 API。**

## 七、一句话

**embedding API 参数在重构前就已是无效透传，当前删除方向对，但属“半完成的 B”；本方案把表/DS 向量召回正式收成 settings + steps/schema|datasource 单路径，同时修掉 create_chat 次序真回归与 DYNAMIC_DS_TYPES/死代码半清理，禁止再给 LLMService 打补丁式 kwargs。**
