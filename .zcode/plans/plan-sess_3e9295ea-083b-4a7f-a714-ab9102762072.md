# 裸机部署打包方案：本地一键打包 + 服务器一键安装

## 目标
本机执行一条命令，生成一个含「源码 + 构建产物 + 已渲染配置」的 tar.gz；手动上传到服务器后，解压再跑一条 `install.sh` 即完成部署。不改动后端代码、不影响本地 dev 启动。

## 新增文件清单（全部新建，不碰现有代码）

### 1. `deploy/envs/.env.server` — 服务器后端环境模板
- 基于本地 `.env` 结构，把环境相关值改为占位符：
  - `__SERVER_IP__`：用于 `FRONTEND_HOST`、`BACKEND_CORS_ORIGINS`、`SERVER_IMAGE_HOST`
  - 路径全部写死为 `/opt/sqlbot/...`（部署目录）
  - `POSTGRES_SERVER=127.0.0.1`（同机 PG）
  - Embedding 沿用云端 OpenAI 兼容（`EMBEDDING_PROVIDER=openai`，`atk.llschain.com`）
- 密钥类（`SECRET_KEY`/`POSTGRES_PASSWORD`/`EMBEDDING_API_KEY`）也用占位符 `__SECRET_KEY__` 等，由打包脚本从本地 `.env` 自动继承填充
- 该模板文件可安全提交（无真实密钥）

### 2. `deploy/systemd/sqlbot.service` — 主后端服务模板
- `ExecStart=/opt/sqlbot/app/.venv/bin/uvicorn main:app --host 0.0.0.0 --port 8000 --workers 2 --proxy-headers --forwarded-allow-ips='*'`
- `WorkingDirectory=/opt/sqlbot/app`，`EnvironmentFile=/opt/sqlbot/.env`
- `__USER__` 占位（默认 root）

### 3. `deploy/systemd/sqlbot-mcp.service` — MCP 服务模板
- `ExecStart=...uvicorn main:mcp_app --host 0.0.0.0 --port 8001 ...`
- 其余同上

### 4. `deploy/nginx/sqlbot.conf` — nginx 站点模板
- `server_name __SERVER_IP__`
- `root /opt/sqlbot/frontend/dist`
- `/api/v1/` → `proxy_pass http://127.0.0.1:8000`（SSE：`proxy_buffering off`、`proxy_read_timeout 300s`）
- `/mcp/` → `proxy_pass http://127.0.0.1:8001/`（带 WebSocket Upgrade 头）
- `/` → SPA `try_files $uri $uri/ /index.html`

### 5. `deploy/install.sh` — 服务器端一键安装脚本
- 检查 Python3.11 / Node / PM2 / PostgreSQL 是否就绪，缺失则打印安装命令提示（不自动装，避免越权）
- 把 `sqlbot.service` / `sqlbot-mcp.service` 复制到 `/etc/systemd/system/`，`sqlbot.conf` 到 `/etc/nginx/conf.d/`
- `systemctl daemon-reload && systemctl enable --now sqlbot sqlbot-mcp`
- `nginx -t && systemctl reload nginx`
- 跑 `cd /opt/sqlbot/app && uv run alembic upgrade head`（迁移）
- 提示 `cd g2-ssr && npm install && pm2 start ecosystem.config.js`
- 打印访问地址 + 初始账号

### 6. `scripts/pack-server.sh` — 本机打包脚本
用法：`./scripts/pack-server.sh <SERVER_IP> [SSH_USER]`（SSH_USER 默认 root）

流程：
1. 校验 `SERVER_IP` 参数
2. 构建前端：`cd frontend && npm run build`（产物在 `frontend/dist`）
3. 从本地根 `.env` source 出密钥变量（`set -a; source .env; set +a`）
4. 清理并创建暂存目录 `dist-pack/sqlbot/`
5. 暂存内容：
   - `backend/*` → `dist-pack/sqlbot/app/`（排除 `venv`/`.venv`/`__pycache__`）
   - `frontend/dist` → `dist-pack/sqlbot/frontend/dist`
   - `g2-ssr/*` → `dist-pack/sqlbot/g2-ssr/`（排除 `node_modules`，保留 `Arial_Unicode.ttf`）
   - `deploy/install.sh` → `dist-pack/sqlbot/deploy/install.sh`
   - 创建 `data/{excel,file,images,logs,models}` 空目录
6. 渲染配置（`sed` 替换占位符）：
   - `deploy/envs/.env.server` → `dist-pack/sqlbot/.env`（填 `__SERVER_IP__` + 密钥）
   - `deploy/systemd/*.service` → `dist-pack/sqlbot/deploy/`（填 `__USER__`）
   - `deploy/nginx/sqlbot.conf` → `dist-pack/sqlbot/deploy/sqlbot.conf`（填 `__SERVER_IP__`）
7. 打包：`tar -czf sqlbot-server-<时间戳>.tar.gz -C dist-pack sqlbot`
8. 输出包路径 + `scp` 上传命令 + 服务器端 3 条命令提示

## 产出包布局（服务器解压后即 `/opt/sqlbot`）
```
/opt/sqlbot/
├── .env                  # 已渲染，backend 的 app/../.env 指向它
├── app/                  # 后端源码
├── frontend/dist/       # 已构建
├── g2-ssr/               # 源码 + ttf
├── deploy/
│   ├── install.sh
│   ├── sqlbot.service
│   ├── sqlbot-mcp.service
│   └── sqlbot.conf
└── data/{excel,file,images,logs,models}/
```

## 服务器端操作（最终只需 3 条命令）
```bash
sudo tar -xzf sqlbot-server-<ts>.tar.gz -C /opt
cd /opt/sqlbot/g2-ssr && sudo npm install && sudo pm2 start ecosystem.config.js && pm2 startup && pm2 save
cd /opt/sqlbot/deploy && sudo ./install.sh
```

## 不影响本地的保证
- 后端 `config.py` 不改，仍读 `../.env`（本地 dev 不变）
- 本地根 `.env` 只读不写
- `frontend/.env.production` 已正确（`./api/v1`），不改
- 所有新增物在 `deploy/` 与 `scripts/pack-server.sh`，与现有代码隔离
- `dist-pack/` 和 `*.tar.gz` 加入 `.gitignore`

## 实施步骤
1. 创建 `deploy/` 目录及 4 个模板文件 + `install.sh`
2. 创建 `scripts/pack-server.sh` 并 `chmod +x`
3. 给 `.gitignore` 追加 `dist-pack/` 和 `sqlbot-server-*.tar.gz`
4. 用你本地 IP 跑一次 `./scripts/pack-server.sh <IP>` 验证产物结构（不实际部署）
