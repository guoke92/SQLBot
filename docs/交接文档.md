# AI智能问数 交接文档

日期：2026-10-30。给接手本仓库的维护者。本文写的是**当前仓库的实际运行方式**，不是上游 `dataease/sqlbot` 镜像的通用说明。

## 1. 这是什么

AI智能问数是基于大模型和 RAG 的对话式问数（ChatBI）。用户用自然语言提问，系统召回表、字段、术语和问数 Wiki，生成 SQL，在已配置的数据源上执行，并把结果画成图表。

本仓库在上游 SQLBot 上继续开发，已经包含这些本地能力，**不会**出现在公开 Docker 镜像 `dataease/sqlbot` 里：

- 统一对话图：查询、分析、预测共用 `backend/graphs/current/chat.yaml`
- 问数 Wiki：页面契约、语料导入、运行时召回、独立的 Wiki 维护对话
- 目录画像与 schema 向量
- 智能问数管理（问答审计、点赞/点踩）
- 服务器打包发布（`./package.sh` → `/opt/sqlbot`）

许可证是 FIT2CLOUD Open Source License（GPLv3 加限制）。二次开发不能替换 Logo 和版权信息。商业授权联系 `support@fit2cloud.com`。

## 2. 仓库怎么分

| 路径 | 作用 |
|---|---|
| `backend/` | FastAPI。问数、数据源、权限、Wiki、对话图都在这里 |
| `frontend/` | Vue 3 + Vite + Element Plus。Hash 路由 |
| `g2-ssr/` | Node 图表服务（AntV G2），给 MCP / 嵌入出图 |
| `backend/graphs/current/` | 生产对话图的 YAML，拓扑只改这里 |
| `backend/templates/` | SQL 生成提示词和各数据库示例 |
| `docs/wiki/` | 问数 Wiki 契约。`v3/` 是可导入的 L1 草稿 |
| `docs/wiki-knowledge/` | 提取用的文档源，不是运行时语料 |
| `deploy/` | 服务器安装、systemd、nginx、环境模板 |
| `scripts/pack-server.sh` | 打包实现，入口是仓库根的 `./package.sh` |
| `sqlbot-dev.sh` | 本机开发启停 |
| `installer/` | 上游裸机安装器（`sctl`）。本仓库日常发布不走这条 |

配置文件在**仓库根**的 `.env`，不在 `backend/` 下。`.env` 不入库。密钥、数据库密码、模型地址单独交接，不要写进文档或聊天记录。

## 3. 用户能做什么

浏览器入口按部署方式不同：

- 本机开发：`http://localhost:5173`，接口 `http://localhost:8000`
- 服务器：nginx `3001`，静态前端 + 反代 API
- 上游 Docker 镜像：`http://<主机>:8000`（那是另一套产物，见第 6 节）

登录后主要页面：

| 路由 | 功能 |
|---|---|
| `/chat` | 智能问数。选数据源后提问，流式返回答案、SQL、图表 |
| `/dashboard` | 仪表板 |
| `/ds` | 数据源、表和字段 |
| `/set/member`、`/set/permission` | 成员与行级/列级权限 |
| `/set/professional`、`/set/training`、`/set/prompt` | 术语、SQL 示例、提示词 |
| `/set/knowledge`、`/set/wiki` | 问数 Wiki 浏览与导入 |
| `/set/wiki/dialogue` | 问数 Wiki 对话。从设置菜单进，不从阅读页进，也不进问数侧栏 |
| `/set/catalog-index`、`/set/schema-vector` | 目录画像、schema 向量 |
| `/system/model` | 大模型配置 |
| `/system/agent-config` | 问数 Agent 配置 |
| `/system/workspace`、`/system/user` | 工作空间、用户 |
| `/system/embedded` | 助手嵌入 |
| `/system/qa-admin` | 智能问数管理：问题、思考链、SQL、结果、反馈 |
| `/system/audit` | 操作审计 |
| `/system/extract-key` | 提取密钥 |
| `/assistant`、`/embeddedPage` | 嵌入页 |

支持的业务库包括 MySQL、PostgreSQL、Oracle、SQL Server、ClickHouse、Doris、StarRocks、Hive、Elasticsearch、达梦、人大金仓、Redshift，以及 Excel/CSV（落到系统库的 Postgres 表）。达梦驱动 `dmpython` 在 macOS 上不安装，本机开发连不上达梦。

大模型走 OpenAI 兼容接口，也支持 Azure、vLLM。具体供应商在系统设置里配，不写死在代码里。

## 4. 一次问数怎么走

1. 前端用 SSE 调 `/api/v1/chat/question`。
2. `apps/api.py` 启动时加载 `backend/graphs/current/*.yaml`。问数走 `submit_graph("chat", …)`。
3. `chat.yaml`：`agent_loop` 和 `execute_tools` 交替，需要澄清时暂停，最后 `finalize_turn` 出图。
4. 工具里完成召回、SQL 生成和执行。查询、分析、预测共用这一张图，不要再提交已经删除的 `analysis` / `predict` 图。
5. 过程写在 `chat_log`。执行详情和页面上的思考链读的是同一条时间线：`GET /chat/record/{id}/timeline`。
6. 接口 JSON 会被包成 `{code, data, msg}`。前端在 `code === 0` 时解开 `data`。流式、MCP、文档接口不包这一层。

生产图：

| graph_key | 文件 | 用途 |
|---|---|---|
| `chat` | `chat.yaml` | 问数、分析、预测 |
| `recommend` | `recommend.yaml` | 推荐问题 |
| `config` | `config.yaml` | 配置助手 |
| `metadata` | `metadata.yaml` | 元数据关系挖掘 |
| `wiki_maintain` | `wiki_maintain.yaml` | 问数 Wiki 维护对话 |

改拓扑只改 YAML。节点实现在 `backend/apps/chat/agent/`、`backend/apps/conversation/`、`backend/apps/knowledge/wiki/maintain/`。

## 5. 问数 Wiki（接手后最容易改坏）

权威契约在 `docs/wiki/README.md`。运行时用的是数据库里的 `wiki_page` / `wiki_corpus`，不是直接读 `docs/wiki/v3` 文件。`docs/wiki/v3` 只作为导入和打包材料。

必须守住的边界：

- 页面正文只有 `backend/apps/knowledge/wiki/materialize.py` 的 `materialize` 能写。状态只有 `promote` 能改。对话图不能直接改页面。
- 对话只提案。用户逐条确认后才落页。没有新知识就停，不要为了有输出去建空白页。
- 页面正文不要加「维护说明」标题，也不要写「来源：」行。来源在 frontmatter 的 `sources`。
- 引用原始问数只存指针 `conversation:{chat_id}/{record_id}`，不复制一份对话。预览按智能问数管理的组件渲染。
- Wiki 对话不出现在问数侧栏（`chat_type=wiki`）。
- 不要把结果写回 `docs/wiki/v3`。不要恢复已废弃的 KnowledgePackage 提交流程。
- 新迁移从当前头 `112a1b2c3d4e5`（`backend/alembic/versions/112_wiki_provenance.py`）往后加。不要改写 `111`、`112`。

## 6. 本机开发

依赖：Python 3.11、Node、pnpm、本机 PostgreSQL（库名 `sqlbot`）、可选 Ollama（本地向量）。

两套 Python 环境，不要混用：

| 场景 | 解释器 |
|---|---|
| 本机开发和 pytest | `backend/venv`。这里才有 `jwt` 和 `sqlbot_xpack` |
| Docker / 服务器 `uv sync` | `backend/.venv` |

`sqlbot_xpack` 是私有包，从 testpypi 安装，仓库里没有源码。`uv sync` 需要能访问那个索引。本地 `venv` 里的 xpack 版本可能低于 `pyproject.toml` 的要求，xpack 报错时先核对版本。

常用命令：

```bash
# 仓库根目录
./sqlbot-dev.sh setup-env          # 把向量相关项写进根目录 .env
./sqlbot-dev.sh start all          # 后端 :8000 ，前端 :5173
./sqlbot-dev.sh restart all
./sqlbot-dev.sh status

# 后端
cd backend
venv/bin/uvicorn main:app --host 0.0.0.0 --port 8000 --reload
venv/bin/python -m pytest ../tests -q

# 前端
cd frontend
pnpm install && pnpm dev
```

日志：`data/logs/backend-dev.log`、`data/logs/frontend-dev.log`。

后端启动时会跑 Alembic。改表先加迁移，再重启。

测试用 `backend/venv/bin/python -m pytest`。不要用 `backend/.venv` 跑全量测试，那个环境缺包，会误报成大面积收集失败。`backend/venv` 里没有 mypy。Ruff 用 `backend/venv/bin/ruff`。`backend/apps/chat/api/chat.py` 有历史 lint，不要对整文件做 `ruff --fix`。

前端格式：单引号、无分号、es5 尾逗号、100 列、2 空格。

## 7. 发布部署

本仓库上线走**源码包 + 裸机**，目标目录 `/opt/sqlbot`。不要用 `docker pull dataease/sqlbot` 代替这次发布，公开镜像没有本仓库的 Wiki、对话图和打包配置。

### 7.1 本机打包

在仓库根目录，且根目录 `.env` 里已有 `SECRET_KEY`、`POSTGRES_PASSWORD`。向量地址和密钥会从这份 `.env` 填进服务器模板 `deploy/envs/.env.server`。

```bash
./package.sh                  # 前端没变会跳过 install/build
./package.sh --force-build    # 前端有改动但指纹没触发时强制构建
```

产物：`sqlbot-server-<时间>.tar.gz`。包里有后端源码、前端 `dist`、`g2-ssr`、`deploy` 脚本、渲染好的 `.env`、`docs/wiki/v3`。不含 `venv` / `node_modules`。

### 7.2 服务器安装或升级

服务器需要：root、PostgreSQL、`uv`、`npm`、nginx、systemd。首次还要有能跑起来的系统库。

```bash
scp sqlbot-server-*.tar.gz <主机>:/tmp/
ssh <主机>
cd /tmp && tar -tzf sqlbot-server-*.tar.gz | head    # 确认包内是 sqlbot/
# init.sh 自己解压到 /opt，把包留在 /tmp 即可
sudo bash -c 'tar -xOf /tmp/sqlbot-server-*.tar.gz sqlbot/init.sh > /tmp/init.sh && bash /tmp/init.sh /tmp/sqlbot-server-*.tar.gz'
```

更常见的做法是解出包后执行包内脚本（脚本会再次按 `/tmp` 下最新包解压覆盖）：

```bash
sudo /opt/sqlbot/init.sh /tmp/sqlbot-server-<时间>.tar.gz
```

`deploy/init.sh` 会：停 `sqlbot`、`sqlbot-mcp` 和 g2-ssr；删旧文件但保留 `data/`、`app/.venv`、`g2-ssr/node_modules`；解压；`uv sync --frozen --no-dev --extra cpu`；`npm install`；安装 systemd 和 nginx；重启并跑 `health.sh`。

### 7.3 服务器进程

| 进程 | 端口 | 怎么管 |
|---|---|---|
| 后端 `uvicorn main:app` | 8000 | `systemctl status sqlbot` |
| MCP `uvicorn main:mcp_app` | 8001 | `systemctl status sqlbot-mcp` |
| g2-ssr（PM2） | 3000，仅本机 | `/opt/sqlbot/status.sh` |
| nginx | 3001 对外 | `/etc/nginx/conf.d/sqlbot.conf` |
| PostgreSQL | 5432 | 系统服务，数据不在应用包里 |

启停：

```bash
sudo /opt/sqlbot/start.sh
sudo /opt/sqlbot/stop.sh
sudo /opt/sqlbot/restart.sh
sudo /opt/sqlbot/status.sh
sudo /opt/sqlbot/health.sh
```

健康检查看四项：后端 `/xpack_static/license-generator.umd.js`、MCP `:8001`、g2-ssr `:3000`、前端 `:3001`。

日志：`journalctl -u sqlbot -u sqlbot-mcp`，以及 `/opt/sqlbot/data/logs`。

nginx 对 `/api/v1/` 关了缓冲，读超时 300 秒，否则问数 SSE 会被截断。上传限制 50m。

### 7.4 上游 Docker（仅作对照）

`docker-compose.yaml` 和根目录 `Dockerfile` 是上游一键镜像：容器内自带 Postgres，对外 8000 / 8001。那条路径**不包含**本仓库 `deploy/` 的 nginx 3001 布局。给别人演示上游原版可以用它；交付当前功能用第 7.1–7.2 节。

`installer/install.sh` 是另一套 `sctl` 安装器，同样不是当前服务器的升级入口。

## 8. 配置与账号

本地 `.env` 由 `backend/common/core/config.py` 读取，路径是 `../.env`。服务器用 `/opt/sqlbot/.env`，来自 `deploy/envs/.env.server` 的占位符替换。

交接时单独给接收人的内容：

- 仓库根 `.env`（本地库密码、`SECRET_KEY`、模型与向量密钥）
- 服务器 `/opt/sqlbot/.env`
- 管理员账号。上游镜像文档写的是 `admin` / `SQLBot@123456`。服务器模板 `deploy/envs/.env.server` 里的 `DEFAULT_PWD` 不同。以目标环境 `.env` 里的 `DEFAULT_PWD` 为准，上线后改掉
- 业务数据源账号、已配置的大模型地址

`SECRET_KEY` 一换，已签发的登录态失效。不要把密钥打进 git。

向量：本地 `./sqlbot-dev.sh setup-env` 会写成 Ollama（`jina-embed`，`localhost:11434`）。服务器模板写成 OpenAI 兼容，地址来自打包时的本地 `.env`。两套不要互相覆盖后不检查。

`CACHE_TYPE=memory` 时不要起多个后端进程。当前 systemd 就是 `--workers 1`。

## 9. 注意事项

- 改对话行为先看 YAML，再看 Python。不要在 Python 里另接一套图。
- 问数轮次的字段约束在 `backend/apps/chat/turn_contracts.py`。澄清卡片在 `backend/apps/chat/semantic_planning.py`。
- 模型连接被拒绝（`APIConnectionError` / connection refused）不再重试。页面类型是 `model-unavailable`，文案在 `frontend/src/i18n/*.json` 的 `chat.model-unavailable`。限流、超时、连接重置仍然重试。用户看到「请稍后重试」时，先区分是不是模型地址拒绝连接。
- 执行详情只走 `chat_log`，不要再造一套 trace 表。
- 用户可见文案走 i18n：`frontend/src/i18n/` 与 `backend/locales/`，语言是 `zh-CN`、`en`、`zh-TW`、`ko-KR`。
- 权限装饰器依赖 `RequestContextMiddleware`。新接口要鉴权时沿用 `@require_permissions`，变更类接口沿用 `@system_log`。Wiki 路由不要引入 `system_log`。
- Excel/CSV 上传目录是 `EXCEL_PATH`。容器里是 `/opt/sqlbot/data/excel`，服务器包同样在 `/opt/sqlbot/data/excel`。
- g2-ssr 依赖 `node-canvas` 和中文字体。图表服务挂了，问数文本仍可能成功，嵌入出图会失败。
- macOS 打包已关 AppleDouble。若 Linux 解压后出现 `._*` 导致 Python 扫到坏文件，重新用 `./package.sh` 打，不要在 Finder 里再压一份。
- `init.sh` 会删 `/opt/sqlbot` 下除 `data`、`app/.venv`、`g2-ssr/node_modules` 以外的旧文件。不要把只存在于服务器、仓库里没有的脚本放在这些目录的顶层。
- 数据库迁移失败时先看后端日志，不要手改 `alembic_version`，除非已经确认库结构和迁移文件不一致。

## 11. 接手第一天建议核对

1. 拿到根目录 `.env` 和服务器 `/opt/sqlbot/.env`，确认库能连、模型地址能通。
2. `./sqlbot-dev.sh status`，后端 `/docs` 和前端首页能开。
3. 用一个已有数据源提一个已知能回答的问题，看思考链、SQL 和图表。
4. 打开 `/system/qa-admin` 和 `/set/wiki`，确认语料已导入，而不是只有 `docs/wiki/v3` 文件。
5. 在测试环境走一遍 `./package.sh` 和 `init.sh`，确认 `health.sh` 四项都过。不要在未备份 `/opt/sqlbot/data` 和 Postgres 的机器上第一次试升级。
