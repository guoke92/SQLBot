# 供票系统集成

供票系统集成是[[产融平台]]V1.7版本中最大的新增功能模块，目标是将[[供票系统]]（供应链票据系统）全面接入产融平台，实现统一登录、建档、待办和消息通知。

## 需求背景

供票系统拟接入到产融平台的门户上面来，企业统一从产融上做登录。供票系统无存量的业务数据，故不用考虑做历史数据迁移。开展供票业务需要资质，公司没有资质，但与第三方平台签署了合作协议，有业务进件后，供票系统将业务申请推送给该平台，该平台再推送给票交所。

## 客户端需求

1. **统一登录**：登录统一从产融平台登录
2. **通用建档**：使用产融平台的通用[[企业认证|建档]]功能
3. **产品开通**：开通供票产品时，先展示供票产品的信息介绍页，点击"立即开通"时跳转至供票页面进行后续操作，所有操作完成后才算产品开通完成
4. **产品切换**：登录后左上方切换产品时可以选到供票
5. **待办接入**：待办接入供票的待办
6. **消息通知**：消息通知接入供票的消息通知
7. **经办人管理**：新增经办人统一使用产融的入口
8. **角色权限**：新增角色使用产融的入口，但为角色配置权限使用供票的页面（产融需改动）
9. **附加信息展示**：供票系统顶部导航栏上的其他信息（如票交所营业时间），需进入供票系统后在下一级展示
10. **协议推送**：企业维度相关的协议需推送到产融

## 内管端需求

1. **产品大类**：新增"供应链票据"，产品介绍信息由供票提供
2. **租户信息推送**：产融新增租户后，当对应租户下开通了供票产品，租户信息要推送给供票系统；进行"产品配置"时，为各个角色配置菜单权限使用供票系统的界面（参考[[订单融资]]的模式）
3. **企业信息推送**：当企业关联了供票的项目时，企业信息推送给供票系统
4. **项目处理**：供票侧没有项目的概念，暂时先默认使用一个固定的项目
5. **变更通知**：企业信息及用户信息变更之后需要通知供票系统
6. **角色支持**：供票系统支持的角色包括"核心企业"和"供应商"，支持的组合仅为"核心企业+供应商"

## 待确认事项

| 待确认项 | 说明 |
| --- | --- |
| 固定项目多租户问题 | 固定项目在多租户场景下的处理方式 |
| 无项目模式 | 需针对供票产品特殊处理，且没有项目的情况下无法发运营二维码 |
| 审批流迁移 | 审批流是否迁移到产融配置 |
| 供票协议 | 供票系统的协议类型和内容确认 |

## 差异点分析

供票系统集成与现有业务系统（如[[多级流转]]、[[线上保理]]）的集成存在显著差异：
- 供票系统无存量数据，不需要历史数据迁移
- 供票系统无"项目"概念，需要特殊处理
- 供票业务需要资质，通过第三方平台间接对接票交所
- 角色组合固定为"核心企业+供应商"
