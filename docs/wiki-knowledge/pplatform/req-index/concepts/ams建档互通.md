# AMS建档互通

AMS建档互通是[[产融平台]]与[[AMS]]（资产管理系统）之间企业建档信息的双向同步与流程协同机制。V1.16版本对该方案进行了细化，旨在深化系统集成，减少企业重复操作，是平台生态扩展的重要一环。

## 核心目标

实现两个系统间企业建档信息的自动同步与角色协同，避免企业在两个系统中重复建档，并确保数据一致性。

## 关键配置

在产融平台内管的互通产品配置中增加了两项关键配置：
1.  **对应客户端角色**：配置哪些角色（供应商、项目公司、核心企业、资金方）可以看到该互通产品，支持多选。
2.  **使用范围标识**：选择“全部”则该贴牌下所有用户可见；选择“特定范围”则只有关联到指定项目下的企业才可见。

## 四种前提场景处理逻辑

方案详细定义了在不同前提条件下，产融平台的处理流程：

1.  **企业信息一致，且产融已建档完成**：
    - 若AMS传递的企业角色与产融侧一致，无需额外处理。
    - 若角色不一致（如AMS传“项目公司”，产融是“供应商”），则产融侧自动发起“增加企业角色”的变更流程。

2.  **企业信息一致，但联系人信息不一致，且产融已建档完成**：
    - 处理逻辑同场景1。AMS的新联系人进入AMS后会再次建档，产融将已有的企业信息（企业+法人）推送至AMS。

3.  **产融无建档记录（包括曾建档但被拒绝）**：
    - AMS导入资产后向产融发送通知，由产融平台拉起建档流程并向联系人发送邀请消息。
    - 建档完成前不显示AMS产品入口；建档完成后，产品入口可见性与“使用范围标识”联动。

4.  **产融侧已有在途建档记录，AMS又推送新信息**：
    - **管理员分配**：同一企业，首次发起建档的人员为管理员。若企业仅做AMS产品，则AMS推送的第一人为管理员；若已做其他产品，则AMS推送的所有人员均为经办人。
    - **经办人可见性**：管理员在建档中时，经办人也可以看到AMS产品入口并进入AMS发起流程。
    - **状态不一致处理**：若管理员建档失败但经办人建档成功/中，考虑将经办人的企业状态统一处理为“已认证”，以解决用户在产融平台看到“建档失败”却能进入AMS操作的认知矛盾。
    - **角色与管理员同步**：若产融在途建档对应A角色，AMS推送人员对应B角色，新增角色时将A角色的管理员也作为B角色的管理员。

## 变更处理（后续版本）

本期暂不实现变更功能的互通。后续版本计划：
- AMS相关变更引导用户至AMS内管操作。
- 企业基础信息、法人信息、联系人信息的变更需在两个系统间广播。

## 复杂性

该方案是V1.16版本中最复杂的需求，考虑了多种边缘情况和并发场景，特别是管理员与经办人状态不一致的处理，体现了深度系统集成的技术挑战。
