# 分布式用户管理

## 概念定义

分布式用户管理是产融平台V1.11版本引入的架构模式，指将经办人的用户管理功能（新增、编辑、权限分配）从产融平台集中管理调整为各业务系统（多级流转、订单融资、线上保理、国内信用证）分布式独立维护的管理方式。

## 背景与动机

### 问题识别

存量产品和新产品在用户权限管理上采用不同的交互模式：

| 系统类型 | 代表系统 | 权限管理模式 | 特点 |
|----------|----------|--------------|------|
| 存量产品 | 多级流转、订单融资 | 直接授权模式 | 无角色概念，直接将菜单赋予用户 |
| 新产品 | 线上保理、国内信用证 | RBAC模式 | 先创建角色并分配权限，再将角色关联到用户 |

### 决策依据

1. **学习成本**：不同产品交互方式不一，统一集成会增加用户困惑
2. **改造成本**：存量系统做统一改造的成本巨大
3. **系统差异**：各业务系统有其独特的业务流程和用户管理需求

## 架构设计

### 整体架构

```
┌─────────────────────────────────────────────────────────┐
│                      产融平台                            │
│  ┌─────────────────────────────────────────────────┐   │
│  │              用户中心（只读查看）                  │   │
│  │  - 展示所有业务系统的用户信息                      │   │
│  │  - 不可做新增、删除、冻结等操作                    │   │
│  │  - 显示关联产品、创建人、更新人等字段              │   │
│  └─────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────┘
                           ▲
                           │ 数据同步
        ┌──────────────────┼──────────────────┐
        │                  │                  │
        ▼                  ▼                  ▼
┌──────────────┐  ┌──────────────┐  ┌──────────────┐
│   多级流转    │  │   订单融资    │  │   线上保理    │
│  用户管理     │  │  用户管理     │  │  用户管理     │
└──────────────┘  └──────────────┘  └──────────────┘
        │                  │                  │
        └──────────────────┼──────────────────┘
                           │
                           ▼
                  ┌──────────────┐
                  │   国内信用证   │
                  │  用户管理     │
                  └──────────────┘
```

### 数据同步机制

#### 手机号校验与模糊匹配
- 新增用户时校验手机号是否已存在于产融侧该企业名下
- 录入手机号时查询产融侧该企业下的用户手机号进行模糊匹配
- 剔除本产品下的用户手机号
- 支持新增全新手机号
- 选择已存在手机号时自动带出用户信息，不可在当前页面修改

#### 用户数据同步规则
1. **新增同步**：业务系统新增用户时需向产融同步用户数据
2. **修改同步**：同一企业同一用户在多系统存在时，任一系统修改需同步产融
3. **级联同步**：产融收到修改后需同步至其他业务系统，保持信息一致性

#### 字段调整
- 手机号字段上移至用户类型下方
- 手机号中间4位不隐藏
- 姓名字段调整为必填
- 修改企业信息时手机号和用户名不可修改

### 产融平台用户中心改造

| 改造项 | 说明 |
|--------|------|
| 菜单结构 | 去除所有二级菜单，升级为一级菜单"用户中心" |
| 操作权限 | 仅展示信息，不可做新增、删除、冻结等操作 |
| 新增字段 | 关联产品（多产品以"、"隔开）、更新人、用户类型 |
| 字段释义 | 创建人/时间指首次创建，更新人/时间指最近一次更新 |

### 特殊场景处理

- **跨系统用户**：一个用户可能在多级流转系统上被创建，在线上保理系统上被修改
- **冻结/解冻**：为单渠道操作，不影响其他业务系统
- **消息发送**：新增经办人后的消息发送由产融平台负责，首次添加时发送，新增其他产品权限时不重复发送

## 各系统改造要点

### 多级流转
- 不区分贴牌是否迁移，用户管理功能均在客户端展示
- 改造点与通用规则一致

### 订单融资
- 取消已迁移贴牌项目隐藏用户管理菜单
- 重新开放用户管理相关功能
- 改造点与通用规则一致

### 线上保理
- 不区分贴牌是否迁移，用户管理功能均在客户端展示
- 改造点与通用规则一致

### 国内信用证
- 原使用产融平台用户中心功能
- 需将该模块功能迁移至国内信用证客户端
- 改造点与通用规则一致

### AMS
- 整体调整为互通类产品
- 不再做用户信息同步处理

## 优势与挑战

### 优势
1. **降低学习成本**：用户在各系统中使用熟悉的管理界面
2. **尊重系统差异**：允许各系统保持其原有的用户管理方式
3. **降低改造成本**：避免对存量系统进行大规模统一改造
4. **灵活性**：各系统可根据自身业务特点进行定制化管理

### 挑战
1. **数据一致性**：需确保多系统间用户数据的实时同步
2. **用户体验碎片化**：不同系统的管理界面可能差异较大
3. **并发处理**：需考虑多系统同时向产融推送数据时的冲突处理
4. **维护成本**：需维护多个系统的用户管理模块

## 性能要求

需考虑并发时的处理，特别是当两个系统同时向产融平台推送数据且数据主键一致时的处理机制。

## 实施建议

1. **同步协议标准化**：制定统一的用户数据同步协议，确保各系统严格遵守
2. **冲突处理机制**：建立完善的并发冲突检测和解决机制
3. **监控告警**：建立数据同步监控和异常告警机制
4. **用户引导**：为用户提供清晰的操作指引，减少学习成本
