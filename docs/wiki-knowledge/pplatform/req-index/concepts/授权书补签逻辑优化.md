# 授权书补签逻辑优化

## 概念定义

授权书补签逻辑优化是产融平台V1.11版本对授权书补签机制的改进，通过在企业维度增加控制开关，使运营人员能够根据企业线下实际签署情况灵活调整是否需要补签授权书，解决了原有根据建档渠道判断的刚性逻辑无法覆盖的业务场景。

## 背景与问题

### 原有逻辑

原有授权书补签判断逻辑：
- **新渠道建档**：默认历史建档时使用新版授权书，不需要补签
- **旧渠道建档**：默认历史建档时使用旧版授权书，需要补签

### 问题场景

存在一种场景：核心企业建档时使用的是旧渠道，但线下签署的授权书已经是最新版本。按照原有逻辑，该企业使用新产品时会触发不必要的补签流程。

## 优化方案

### 企业维度控制开关

#### 开关状态逻辑

| 建档渠道 | 系统默认状态 | 操作项显示 | 说明 |
|----------|--------------|------------|------|
| 旧渠道 | 需要补签 | "关闭授权书补签" | 业务系统传值"是否需要补签授权书"为"是" |
| 新渠道 | 不需要补签 | "开启授权书补签" | 业务系统传值"是否需要补签授权书"为"否" |

#### 开关操作规则

1. **手动调整**：内管用户可根据实际情况手动调整开关状态
2. **按钮消失条件**：
   - 企业已在产融平台做过一次授权书补签（包含授权书变更）
   - 企业是在产融平台上新增建档的

#### 字段层级

```
业务系统传值（初级）
    ↓
产融平台处理
    ↓
结合运营手动修改 + 实际是否已重签
    ↓
终极"是否需要补签授权书"字段
    ↓
客户端是否触发补签流程
```

### 补签流程触发节点

**触发时机**：企业开通新产品时

**判断逻辑**：
1. 检查终极"是否需要补签授权书"字段
2. 如需要 → 触发授权书补签流程
3. 如不需要 → 直接进入产品开通流程

**重要规则**：只要企业在产融平台上做过一次补签，后续不再触发补签。

## 存量数据处理

### 线上保理已补签企业
- 迁移到产融后不需要再次触发补签
- 需手动处理一次数据

## 关联系统处理

### 业务系统改造
- 原有的补签授权书逻辑需要去掉
- 例如：线上保理系统上的补签逻辑需移除

## 操作流程

### 运营人员操作流程

1. **查看企业列表**：在产融平台内管查看存量迁移企业列表
2. **识别操作项**：
   - 旧渠道企业：显示"关闭授权书补签"按钮
   - 新渠道企业：显示"开启授权书补签"按钮
3. **手动调整**：根据企业线下实际签署情况调整开关
4. **确认操作**：点击按钮后出现弹窗提示，确认后生效

### 客户端触发流程

1. 企业开通新产品
2. 系统检查终极"是否需要补签授权书"字段
3. 如需补签：进入授权书补签流程
4. 如不需补签：直接进入产品开通流程

## 业务价值

1. **提升灵活性**：运营人员可根据实际情况灵活调整，避免不必要的补签
2. **降低企业负担**：减少企业因历史渠道问题而重复签署授权书的情况
3. **优化用户体验**：简化产品开通流程，提升企业使用效率
4. **数据准确性**：通过终极字段确保补签判断的准确性

## 注意事项

1. **手动处理**：线上保理已补签企业的存量数据需手动处理
2. **系统改造**：业务系统需移除原有的补签逻辑，避免重复触发
3. **操作培训**：运营人员需了解开关的使用场景和判断依据
