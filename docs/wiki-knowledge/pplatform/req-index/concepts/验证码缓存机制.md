# 验证码缓存机制

验证码缓存机制是SSO验证码登录改造中平衡安全性与用户体验的核心设计。它将行为验证码校验成功的结果（连同参数）缓存到 [[redis]]，并在后续登录时复用，以避免用户在短时间内重复进行行为验证。

## 工作原理

1.  **缓存写入**：在 [[行为验证码校验]] 成功且 `loginCaptcha=true` 时，由 [[sso-cache-util]] 将验证码参数（`challenge|validate|seccode`）拼接后存入Redis。
    - **缓存键**：`sso:behavior_captcha:{loginName}#{sysChannel}`
    - **缓存值**：`{challenge}|{validate}|{seccode}`
    - **有效期**：由调用方指定的 `second` 参数决定（建议5-10分钟）。
2.  **缓存读取与校验**：在登录流程中，若直接校验验证码失败，则检查缓存。
    - 使用传入的参数拼接字符串，与缓存值进行比对（[[参数一致性校验]]）。
    - 若一致，则删除缓存（[[一次性使用]]），允许登录。

## 安全考量

- **缓存有效期**：过长会增加安全风险，过短则失去缓存意义。需要运维规范配合。
- **参数一致性**：确保只有使用完全相同的验证码参数才能复用缓存，防止参数替换攻击。
- **一次性使用**：缓存使用后立即删除，防止重放攻击。
