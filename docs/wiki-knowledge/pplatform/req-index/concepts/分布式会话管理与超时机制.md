# 分布式会话管理与超时机制

## 概述

分布式会话管理与超时机制是SSO单点登录系统基于Redis实现的会话生命周期管理方案，确保用户在一定时间不活动后会话自动失效，满足"登录超时自动退出机制且超时时间不大于30分钟"的合规要求。

## 设计目标

- 实现登录超时自动退出，超时时间不大于30分钟
- 支持分布式环境下的会话统一管理
- 提供灵活的超时配置能力
- 通过自动续期机制提升用户体验

## 技术实现

### 会话存储

使用Redis存储用户会话信息：
- **会话Key格式**：`sso:session:{sessionId}`
- **会话信息**：用户ID、登录名、系统编号、登录时间、过期时间等
- **会话过期**：支持可配置的会话过期时间

### 超时配置

| 配置级别 | 说明 | 优先级 |
|---------|------|--------|
| 用户级配置 | 按用户（loginName）配置个性化超时时间 | 最高 |
| 系统级配置 | 按业务系统（sysChannel）配置不同的超时时间 | 中 |
| 默认配置 | 30分钟 | 最低 |

**Nacos配置示例**：
```properties
sso.cookie.expire.minute.sysChannel1 = 30  # 系统1超时30分钟
sso.cookie.expire.minute.sysChannel2 = 20  # 系统2超时20分钟
sso.cookie.expire.minute.user001 = 15       # 用户user001超时15分钟
```

## 核心流程

### 超时检查流程

```
用户访问系统
  ↓
检查Cookie中的sessionId
  ↓
从Redis获取会话信息
  ├── 会话不存在 → 返回未登录（错误码10900）
  └── 会话存在 → 检查是否超时
        ├── 已超时 → 清除会话 → 返回未登录（错误码10900）
        └── 未超时 → 检查是否需要续期
              ├── 需要续期 → 更新过期时间 → 允许访问
              └── 不需要续期 → 允许访问
```

### 自动续期机制

**续期条件**：当前时间 - 最后刷新时间 > 超时时间/2

**续期操作**：
1. 更新Redis中的会话过期时间
2. 更新Cookie的过期时间
3. 保持与Redis会话过期时间一致

### 会话失效处理

会话失效后：
1. 清除Redis中的会话信息
2. 返回未登录错误码 [[sso-result-code-enum|10900]]
3. 要求用户重新登录

## 关键代码逻辑

```java
SsoUser ssoUser = ssoCacheUtil.getCacheSsoUser(cookieName, ssoIdKey);
if (ssoUser != null && version.equals(ssoUser.getVersion())) {
    // 检查是否需要续期
    if (System.currentTimeMillis() - ssoUser.getExpireFreshTime() > ssoUser.getExpireMinite() * 10000) {
        // 更新缓存，续期
        ssoUser.setExpireFreshTime(System.currentTimeMillis());
        loginUtils.putLoginStore(ssoIdKey, ssoUser,
            loginUtils.getRedisExpireMinute(ssoUser.getSysChannel(), ssoUser.getLoginName()));
    }
    // 允许访问
} else {
    // 会话不存在或已过期，返回未登录
    return new SSOResultDTO<>(SSOResultCodeEnum.ERROR_CODE_10900);
}
```

## Cookie管理

- 系统通过Cookie存储sessionId
- Cookie过期时间与Redis会话过期时间保持一致
- 支持"记住我"功能，可设置更长的过期时间（但不超过系统配置的最大值）
