# 产融平台V1.30版本需求文档（0514）.docx

产融平台V1.30版本

需求说明书

修订记录

需求目录

联系人产品及菜单权限展示

用户故事

目前内管端未展示企业联系人开通产品情况以及对应菜单权限，实际业务中常出现管理员未给经办人配置权限无法开展业务，需开发介入查询的情况。本期为减少实际业务中沟通成本，本期将在内管端增加联系人开通产品及菜单权限展示。

详见需求

配置项

无

业务规则描述

内管端

企业联系人

企业联系人列表点击联系人【姓名】字段，弹窗展示联系人基本信息和菜单权限两个tab页。

企业联系人列表

弹窗

基本信息

“基本信息”tab页展示现有点击【姓名】后的联系人基本信息，内容样式与现有一致。

菜单权限

点击“菜单权限”tab页，展示企业联系人在已开通产品下的菜单及按钮权限，包括管理员、经办人。该联系人开通某个产品时展示该产品名称tab页，未开通时不展示。

产融平台、线上保理

样式及交互如下：分为菜单名称、按钮名称，勾选状态为只读样式。支持菜单名称切换，并展示对应按钮名称的勾选状态。

业务逻辑：查询该用户所属角色的菜单权限，多个角色菜单权限时取并集展示。另，产融平台存在系统默认经办人权限，但本期按照角色所属菜单权限展示本期同步展示。

多级流转、订单融资

样式及交互如下：分为菜单名称、审核层级，只读样式。无交互。

业务逻辑：查询该用户在对应系统下的菜单名称、审核层级。

存量数据/在途数据的处理

存量联系人的权限需同步处理。

关联系统及相关改造

上述联系人菜单权限、按钮权限、审核层级数据为业务系统提供，产融平台查询后或业务系统同步后展示。

【导入、导出】支持异步批量处理

用户故事

前期项目运营配置、租户运营配置已支持【导入】和【导出】功能，但考虑系统性能，目前单次处理最大为500条数据，实际业务中运营需批量或全部处理，同时近期方案侧提出增加项目立项统计需求，同样需要批量功能，综上本期增加异步【导入】、【导出】功能。

任务成功

后台：生成导出文件，上传至统一文件服务；

任务失败

后台：记录失败原因、失败时间，任务状态更新为“失败”；

前端：任务中心该任务状态更新为“失败”，操作列显示【下载异常文件】（该文件为错误文件，后端自行定义内容）按钮；

通知：系统右上角弹出“导出任务失败，请前往文件管理查看原因”通知。

用户触发【导入】流程

【导入】数据后，文件上传toast提示“文件已上传，正在后台导入，可在文件管理查看结果”，3秒后自动关闭，弹窗自动关闭。

后台任务执行逻辑

任务优先级：默认按任务创建时间排序（先创建先执行）；

导入任务结果处理

后台：所有数据校验通过并入库；

前端：任务中心该任务状态更新为“成功”，操作列无按钮。

任务失败

后台：记录失败原因、失败时间，任务状态更新为“失败”；

前端：任务中心该任务状态更新为“失败”，操作列显示【下载异常文件】按钮；

通知：系统右上角弹出“导入任务失败，请前往文件管理查看原因”通知。

【通用】新增项目立项统计页面

用户故事

目前saas产品方案部针对业务立项审批的项目，均采用线下人工维护项目表的操作方式进行，存在耗时长、信息缺漏/未更新等问题；

为避免人工维护信息导致遗漏缺失等情况，也可进一步的减少人工维护成本；将项目统计表线上化，通过系统实现数据统计。

系统功能上线后时间点之后所获取企微立项审批类型为“金融科技业务”所有的立项审批数据，包括已拒绝、审批中、审批通过的数据；——每1小时获取更新企微立项数据。

通过“项目立项统计”页面【新增模拟立项】创建的数据。

“项目立项统计”表单内容

筛选条件

立项审批编号、立项名称、主项目名称、项目类型、产品类型、KA是否贴牌、方案经理、项目阶段、发起立项时间、立项审批状态、首笔落地时间、业务经理、业务中心、运营对接人、资方全称、项目配置名称

立项审批编号、立项名称、主项目名称、方案经理、业务经理、业务中心、运营对接人、资方全称、项目配置名称：均为输入框格式，支持模糊查询；

发起立项时间、首笔落地时间：均为日期选择框，支持选择起始日期-结束日期；

项目类型：下拉单选，字典为：子项目、主项目；

产品类型：下拉单选，字典与企微的【战略客户】项目立项审批中类型为“金融科技业务”对应的产品类型一致；

KA是否贴牌：下拉单选，字典为：是、否

项目阶段：下拉单选，字典为：立项阶段、实施阶段、持续运营、挂起、立项终止

立项审批状态：下单单选，字典为审批通过、审批中、已驳回、已删除、已撤销；

列表展示数据信息：

依据表【项目统计表】线上化需求中第一个sheet表【定稿-最终版】（新版）项目统计看板里面标记的“列表是否展示字段”里面【是】数据进行展示，同时需按照表中字段顺序排列；

“立项名称”数据列的信息字体为蓝色，支持点击进入查看单个立项审批详细信息；

页面数据列表要求固定数据列至“立项名称”数据列（即项目立项名称数据列往后的数据可依据滑动条拖动）；

企微获取回来的数据在此页面进行修改后，后续从企微获取更新数据时不可覆盖已修改的数据，仅更新该数据的“企微立项审批状态”；

以需求为准

0427【通用】客户录入内管调整管理员邮箱非必填

用户故事

近期将有大量企业注册，运营侧内管端录入建档信息，因客户无法提供邮箱但目前系统逻辑为内管录入企业信息时管理员邮箱为必填，对建档流程有一定阻碍，故本期对“客户录入”认证方式的单笔新增企业和批量导入企业时，内管端调整“管理员邮箱”字段为非必填。

业务流程

详见需求

配置项

无

业务规则描述

内管端

认证方式=邀请认证-客户录入时，产融平台内管端企业管理员邮箱调整为非必填。包括单笔【新增】企业和【批量导入】企业。

单笔新增

单笔【新增】/【编辑】企业信息时，调整管理员“业务邮箱”字段为非必填，同时取消相关必填校验。

批量导入

批量导入-客户录入模板中，“客户管理员业务邮箱”字段去掉“（必填）”字样，同时取消相关必填校验。

关联系统及相关改造

此前该邮箱字段为必填是基于登录时无法收到短信验证码，可使用邮箱接收，本期调整为非必填可能存在无法登录的场景，运营侧反馈：如收不到短信验证码时联系运营去录入内管的邮箱，然后再去获取。或者后续排期优化可以就是首次登录内管没有邮箱的话，支持客户自己登录页面录入。考虑系统功能优化，短期将采用联系运营录入方式处理。
