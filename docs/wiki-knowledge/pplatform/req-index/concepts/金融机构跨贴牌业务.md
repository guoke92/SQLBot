# 金融机构跨贴牌业务

## 概述

金融机构跨贴牌业务是产融平台为支持金融机构在多个贴牌下开展业务而设计的功能需求。该需求源于实际业务场景：部分金融机构需要在不同的贴牌（租户）下为不同的客户提供金融服务。

## 核心需求

### 1. 一次建档

金融机构只用建档1次，不用重复建档。无论在哪个贴牌下首次完成[[企业认证]]，后续在其他贴牌下无需再次认证。

### 2. 跨贴牌业务支持

- 金融机构可以跨贴牌做业务
- 非自营的金融机构也可以跨贴牌
- 待确认：待迁移的几个贴牌中是否存在跨租户开展业务的金融机构

### 3. 统一账号登录

当金融机构在多个贴牌下都有做业务时，希望可以使用同一个账号登录多个贴牌。这与[[非手机号账号登录]]的需求相关。

### 4. 数据隔离的差异化需求

不同贴牌下的数据可见性存在差异化需求：

- **登录A贴牌时**：只可以看到A贴牌下做的业务数据
- **登录B贴牌时**：可以看到与该金融机构相关的所有数据

## 技术挑战

1. **数据隔离与共享的平衡**：需要在贴牌级别的数据隔离和金融机构级别的数据共享之间找到平衡
2. **账号体系设计**：需要支持一个账号跨多个租户登录，同时保持数据隔离
3. **认证复用**：需要设计认证信息的跨租户复用机制

## 与现有概念的关系

- 该需求与[[产融平台]]的[[SaaS与本地化统一]]架构目标密切相关
- 数据隔离策略需要与[[租户]]体系的设计保持一致
- 认证复用机制需要与[[企业认证]]流程整合

## 待确认事项

- 产品经理确定待迁移的几个贴牌是否存在跨租户开展业务的金融机构
- 这将决定相关功能的实现范围
